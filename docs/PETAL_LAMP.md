# Petal lamp (`examples/petal_lamp.py`)

已通过实际 Blender 5.2.1 GUI 与官方 MCP SDK 完成建模、六项参数变化/复位验证和保存。
工程：`D:/AI/MCP/Blender/Project/models/petal_lamp.blend`；预览：`Project/previews/petal_lamp.png`（960×960）。
灯体由 Bézier 灯杆、椭球底座、七片实例化花瓣和中央球形灯泡组成，保持几何节点可编辑。
这是造型模型，预览使用 Workbench；尚未配置发光材质或灯光照明。

One bounded MCP-client recipe that builds a simple biomorphic petal lamp with Geometry
Nodes, driving this workspace's `server.py` through the **official** MCP SDK
(`mcp.ClientSession` + `stdio_client`). Every mutation is a typed `blender_*` tool call: no
`bpy` import, no raw JSON bridge and no arbitrary code in Blender; nothing is deleted or
replaced.

## What it builds

Object `Petal_Lamp` at world `[1.2, 0, 0]` (right of the chair recipe), real metres, +Z up,
with node group `GN_Petal_Lamp` and modifier `Petal Lamp`. The geometry origin is the stem
base and the carrier mesh is a single vertex with no faces, because the visible lamp is
generated by the node group and only Group Output is evaluated.

Shape: a flattened oval base (shared UV sphere scaled `[Base Radius, Base Radius, .045]`, on
`z = 0`), a bent Bezier rod with a 12-sided profile, a radial ring of ellipsoid petals opened
by `Opening` radians from vertical (larger values spread the petals outward) and a
central spherical bulb centred on the stem tip: an open flower lampshade.

## Running it

Preconditions: Blender is running with the bridge listening (default port 9876,
`BLENDER_MCP_PORT`) and the project venv exists; the recipe always runs `<MCP>/.venv` Python.

```powershell
cd <workspace>\MCP
.venv\Scripts\python.exe examples\petal_lamp.py --phase stem
.venv\Scripts\python.exe examples\petal_lamp.py --phase flower
.venv\Scripts\python.exe examples\petal_lamp.py --phase verify
.venv\Scripts\python.exe examples\petal_lamp.py --phase save
```

`--phase` is required; `--port` overrides `BLENDER_MCP_PORT` (default 9876). One phase per invocation; a phase that fails prints `[error] ...` and exits non-zero (2).

## Parameters

| Name | Type | Default | Range | Meaning |
| --- | --- | --- | --- | --- |
| `Height` | float (DISTANCE) | 1.10 | 0.6 .. 1.8 | stem height at the tip, metres |
| `Stem Bend` | float (DISTANCE) | 0.22 | 0.0 .. 0.5 | lateral X offset of the stem tip, metres |
| `Petal Count` | int | 7 | 4 .. 12 | number of petals around the head |
| `Petal Length` | float (DISTANCE) | 0.22 | 0.12 .. 0.35 | ellipsoid petal half length, metres |
| `Opening` | float (ANGLE) | 0.65 | 0.2 .. 1.2 | petal opening from vertical, radians; X tilt = pi/2 - Opening |
| `Base Radius` | float (DISTANCE) | 0.20 | 0.12 .. 0.35 | radius of the flattened oval base, metres |

## Graph

Each phase sends its edits as transactional `blender_batch_graph_edit` calls (at most
`BATCH_LIMIT = 100` operations per batch, creates -> socket defaults -> links). Sockets use
the native Blender 5.2 names of this build (Math operands by index, because both display as
`Value`); a wrong name fails the whole batch loudly and rolls the group back untouched.

`stem` creates the group, carrier object and modifier, then builds `Shared_Sphere`
(`MeshUVSphere`, Segments 32 / Rings 16 / Radius 1.0 — the one sphere shared by the base,
the petals and the bulb), the base (`CombineXYZ` centre `[0, 0, .045]` and scale
`[Base Radius, Base Radius, .045]` feeding a `Transform`), the rod (`Stem_Curve`
`CurvePrimitiveBezierSegment` `mode=POSITION`: start `[0, 0, .08]`, start handle
`[0, 0, Height*.6]`, end handle `[Stem Bend, 0, Height*.8]`, end `[Stem Bend, 0, Height]`,
with `Stem_Profile` a `CurvePrimitiveCircle` `mode=RADIUS` Resolution 12 / Radius .015
through `CurveToMesh` with `Fill Caps`), and a `Join_Parts` multi-input node that is also
linked to `Group Output`. The join node must hold exactly 2 part links afterwards.

`flower` appends the head to that join node and is skipped, with a log line, when
`Petal_Instance` and `Bulb_Transform` already exist, so a re-run cannot duplicate geometry:

* `Head_Center = [Stem Bend, 0, Height]` (the stem tip); `Petal_Rings` (`MeshCircle`,
  `fill_type=NONE`, Vertices `Petal Count`, Radius .06) translated onto it is the
  instancing source, not geometry.
* `Petal_Transform`: the shared sphere scaled `[.060, Petal Length, .022]` and translated
  `[0, Petal Length*.75, 0]`.
* `Petal_Index` (`InputIndex`) gives `theta = (2*pi / Petal Count) * Index - pi/2`, and
  `Petal_Rotation = (Opening, 0, theta)`; `InstanceOnPoints` (Points = ring, Instance =
  petal, Rotation) -> `RealizeInstances` -> join.
* `Bulb_Transform`: the shared sphere scaled `.065` at the head -> join (4 part links).

## Verification and outputs

`verify` reads the modifier parameters and evaluated mesh via `blender_object_info`, then
drives three inputs with `blender_set_modifier_input`, restoring each immediately (a
`finally` block restores anything still modified, even after a failure):

1. `Petal Count` 7 -> 9 must increase the evaluated vertex count.
2. `Height` 1.10 -> 1.35 must move `max_z` by `+0.25` m (tolerance 0.010).
3. `Opening` 0.65 -> 0.95 must change the evaluated mesh checksum.

Any failed check exits non-zero without touching the file system. On success the phase renders
a 960x960 isometric preview to `previews/petal_lamp.png` (MCP image content; only metadata is
printed, never the binary) and never overwrites an existing preview.

`save` writes `models/petal_lamp.blend` with `overwrite=false`, no `.blend1` backup and no preview; if the file already exists the phase stops and says so.

## Notes and limitations

* Codex 集成了 `GeometryNodeSetShadeSmooth`（FACE 域）和按依赖层级排列的节点布局。
* 实际联调发现 Blender 浮点插槽的类型为 `VALUE`；桥的数值兼容集合已补齐，整数花瓣数量与 Index 可正确连接 Math 输入。第一次失败批次已回滚，保留灯杆；加载修正后再次编辑成功。
* Nothing is deleted or replaced: an existing `GN_Petal_Lamp` or `Petal_Lamp` stops the `stem` phase, and the recipe never calls `remove_node` or `unlink_socket`; a half-built flower graph stops on the duplicate node-name guard instead of duplicating geometry.
* The live MCP integration run is driven by Codex, not by this file's own test harness.
